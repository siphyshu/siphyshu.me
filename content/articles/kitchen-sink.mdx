This file is a **fixture**, so it renders under `next dev` and is absent from a
production build. Real drafts work differently: a draft lives in
`content/drafts/`, which git ignores, and publishing is moving the file into
`content/articles/`. The repo is public, so a draft never gets committed.

Copy this file to start a new article. Delete everything below the frontmatter.

## Headings are linkable

Every heading gets an `id` and becomes its own anchor — hover one and the URL
fragment is there to copy. That is `rehype-slug` plus `rehype-autolink-headings`
doing the work at build time.

### A third-level heading

Text can be _emphasised_, **strong**, `inline code`, ~~struck through~~, or a
[link to another page](/projects) on this site. An [external
link](https://example.com) opens in a new tab and carries `rel="noopener
noreferrer"`; an [anchor](#headings-are-linkable) stays put.

## Code gets highlighted at build time

Syntax highlighting runs through Shiki while the site builds, so the HTML ships
already coloured and no highlighter is sent to the browser.

```ts
// A tag that isn't in data/tags.ts fails the build, naming the file.
tags: z.array(
  z.string().refine((id) => id in tagRegistry, {
    error: (issue) => `unknown tag "${issue.input}"`,
  })
),
```

```bash
npm run dev   # drafts and fixtures visible
npm run build # both gone
```

## Figures

A plain picture sits in the text, as above. A demo, a chart or a diagram is an
object in the article, so it goes in a `<Figure>`: a numbered card that hangs
into the margin by its own padding, so what's inside it lines up with the text
around it. The numbers come from CSS, so inserting a figure never
means renumbering the rest.

<Figure caption="An image in a card. Its left edge is the paragraph's left edge.">
  <img src="/articles/snake-r4/01.png" alt="An Arduino on a breadboard" />
</Figure>

Anything can go inside one — a component, a canvas, a few buttons:

<Figure caption="Markup inside a card. Long content scrolls inside it rather than widening the page.">
  <div style={{ display: "flex", gap: 4 }}>
    {["s", "n", "a", "k", "e"].map((l, i) => (
      <span
        key={i}
        style={{ width: 40, height: 40, display: "grid", placeItems: "center", background: i < 2 ? "#6aaa64" : "#787c7e", color: "#fff", fontFamily: "ui-sans-serif, system-ui", fontWeight: 600, textTransform: "uppercase" }}
      >
        {l}
      </span>
    ))}
  </div>
</Figure>

And the rare picture that should run edge to edge:

<Figure
  src="/articles/snake-r4/02.png"
  alt="The joystick wired to the board"
  caption={<>A <code>size="full"</code> figure. Its caption stays in the column.</>}
  size="full"
/>

Then back to the column, as if nothing happened. A ==highlight== isn't markdown,
but <mark>a mark element</mark> is, for the one phrase a reader should take
away.

## Notes

A footnote is a caret and a label,[^gfm] and GFM collects them at the end under
"Notes", each with a link back up.[^back]

[^gfm]: GitHub-flavoured markdown's footnote syntax. The label can be any word; they're numbered in order of first use.
[^back]: The ↩ returns to where you were reading.
